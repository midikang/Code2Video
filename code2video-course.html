From Text to Teaching: What Code2Video Does

Understanding how AI turns knowledge points into educational videos

What This System Does

Code2Video is an AI-powered system that transforms knowledge points into complete educational videos. Imagine typing "Explain how neural networks work" and getting back a polished 5-minute animated explainer video with voiceover, visualizations, and smooth transitions.

1
You provide a topic

Type a concept you want explained — "Linear transformations and matrices" or "How Bitcoin mining works"

2
AI creates a teaching outline

The system breaks your topic into learnable sections, like chapters in a textbook

3
AI generates animation code

Each section becomes executable Python code using Manim

4
Code becomes video

The Python code executes, rendering animated scenes into MP4 video files

5
Videos merge into final output

All sections combine into one cohesive educational video with smooth transitions

Why This Matters

Traditional video generation approaches use pixel-based text-to-video models — systems that predict what pixels should look like based on text descriptions. Code2Video takes a different approach: instead of guessing at pixels, it generates executable code that produces mathematically precise animations.

💡
Key Insight: Code as the Medium

By using code instead of pixels, Code2Video ensures accuracy, reproducibility, and clarity. The animations are never "hallucinated" — they're calculated. This is like the difference between asking an artist to draw a graph versus using Excel to plot exact data points.

def generate_outline(self) -> TeachingOutline:
    outline_file = self.output_dir / "outline.json"

    if outline_file.exists():
        with open(outline_file, "r") as f:
            outline_data = json.load(f)
    else:
        prompt1 = get_prompt1_outline(
            knowledge_point=self.learning_topic
        )

        for attempt in range(1, self.max_regenerate_tries + 1):
            response = self._request_api_and_track_tokens(
                prompt1, max_tokens=self.max_code_token_length
            )
            try:
                content = response.candidates[0].content.parts[0].text
                outline_data = json.loads(content)
                break
            except json.JSONDecodeError:
                if attempt == self.max_regenerate_tries:
                    raise
What it means
Check if we already generated an outline: If the JSON file exists, just load it (caching for efficiency).
Otherwise, ask the LLM: Send a prompt asking the AI to break the topic into teachable sections.
Retry logic: Try up to max_regenerate_tries times. If the AI returns invalid JSON, try again.
Token tracking wrapper: The _request_api_and_track_tokens method automatically counts how many tokens we've used (important for cost estimation).

def generate_storyboard(self) -> List[Section]:
    storyboard_file = self.output_dir / "storyboard.json"

    if storyboard_file.exists():
        with open(storyboard_file, "r") as f:
            storyboard_data = json.load(f)
    else:
        prompt2 = get_prompt2_storyboard(
            outline=json.dumps(self.outline.__dict__)
        )

        response = self._request_api_and_track_tokens(
            prompt2, max_tokens=self.max_code_token_length
        )

        json_str = extract_json_from_markdown(content)
        storyboard_data = json.loads(json_str)

        # Save original storyboard
        with open(storyboard_file, "w") as f:
            json.dump(storyboard_data, f)

    # Parse into Section objects
    self.sections = []
    for section_data in storyboard_data["sections"]:
        section = Section(
            id=section_data["id"],
            title=section_data["title"],
            animations=section_data["animations"]
        )
        self.sections.append(section)
What it means
Check cache first: Like outline generation, we reuse existing storyboards to avoid redundant API calls.
Prompt construction: Pass the outline JSON to the LLM and ask it to create detailed animation descriptions for each section.
Extract JSON from markdown: LLMs often wrap JSON in markdown code blocks — we strip that formatting.
Parse into Section objects: Convert the raw JSON into Python dataclasses that the rest of the pipeline can work with.

The LLM Orchestra

How multiple AI models work together through a unified API

Why Multiple Models?

Code2Video doesn't rely on a single AI model. Instead, it can use Claude, GPT-4/GPT-5, or Gemini depending on the task. Why?

🧠
Claude (Anthropic)

Best for: Long-form reasoning, educational content planning. Used for outline and storyboard generation when depth matters.

💬
GPT-4/GPT-5 (OpenAI)

Best for: Code generation, function-level reasoning. Fast and reliable for translating animation descriptions into Python.

👁️
Gemini (Google)

Best for: Multimodal analysis. Can watch videos and provide feedback on visual layout, timing, and clarity. Unique capability.

The API Abstraction Layer

The gpt_request.py file abstracts all model interactions. This means the rest of the codebase doesn't need to know which model is being used. Here's the pattern:

Python 
def request_claude_token(prompt, max_tokens=10000, max_retries=3):
    base_url = cfg("claude", "base_url")
    api_key = cfg("claude", "api_key")
    client = OpenAI(base_url=base_url, api_key=api_key)

    usage_info = {
        "prompt_tokens": 0,
        "completion_tokens": 0,
        "total_tokens": 0
    }

    retry_count = 0
    while retry_count < max_retries:
        try:
            completion = client.chat.completions.create(
                model="claude-4-opus",
                messages=[{"role": "user", "content": prompt}],
                max_tokens=max_tokens
            )

            if completion.usage:
                usage_info["prompt_tokens"] = completion.usage.prompt_tokens
                usage_info["completion_tokens"] = completion.usage.completion_tokens
                usage_info["total_tokens"] = completion.usage.total_tokens

            return completion, usage_info

        except Exception as e:
            retry_count += 1
            delay = (2**retry_count) * 0.1 + random.random() * 0.1
            time.sleep(delay)
What it means
Configuration loading: Read API keys and endpoints from api_config.json so they're not hardcoded.
Token tracking: Every API call records how many tokens were used for prompt (input) and completion (output). This data flows back to TeachingVideoAgent.
Exponential backoff retry: If the API fails (rate limit, network error), wait progressively longer before retrying (0.2s, 0.4s, 0.8s).
Unified interface: Notice this has the same signature as request_gpt4o_token() and request_gemini_token() — interchangeable!

Token Tracking Matters

💰
Why count tokens?

LLM APIs charge by the token. A single video might use 50,000+ tokens across all stages (outline, storyboard, code, feedback). By tracking usage, Code2Video can estimate costs and optimize which models to use for which tasks. For example, using GPT-4o for code generation and Gemini only for video critique balances quality and cost.

Error Fixing Intelligence

How ScopeRefineFixer debugs generated code automatically

The Problem: AI-Generated Code Isn't Perfect

When an LLM generates Manim animation code, it might produce syntax errors, use undefined variables, or call methods that don't exist. Traditional approaches would just regenerate the entire code from scratch — wasteful and slow. ScopeRefineFixer uses a smarter approach: scope-based fixing.

The 3-Tier Fix Strategy

ScopeRefineFixer analyzes the error and decides how much code to regenerate:

1
Single-Line Fix

For simple errors like typos, undefined variables, or syntax mistakes. Only regenerate the problematic line plus 5 lines of context. Example: NameError: 'VGropu' not defined → fix to VGroup.

2
Function-Level Fix

For errors in logic or parameter mismatches. Regenerate the entire function containing the error. Example: TypeError: takes 2 positional arguments but 3 were given.

3
Section Regeneration

For structural issues or multiple cascading errors. Regenerate the entire animation section from the storyboard. Last resort after 10+ failed fixes.

Error Analysis Code

Here's how ScopeRefineFixer categorizes errors to determine fix scope:

Python 
class ManimCodeErrorAnalyzer:
    def __init__(self):
        self.common_manim_errors = {
            "NameError": self._analyze_name_error,
            "AttributeError": self._analyze_attribute_error,
            "TypeError": self._analyze_type_error,
            "SyntaxError": self._analyze_syntax_error,
        }

    def analyze_error(self, code: str, error_msg: str) -> Dict:
        error_info = {
            "error_type": None,
            "line_number": None,
            "fix_scope": "single_line",
            "suggested_fix": None,
        }

        # Parse error message
        error_info.update(self._parse_error_message(error_msg))

        # Analyze based on error type
        if error_info["error_type"] in self.common_manim_errors:
            analyzer = self.common_manim_errors[error_info["error_type"]]
            error_info.update(analyzer(code, error_msg, error_info))

        return error_info

    def _analyze_name_error(self, code, error_msg, error_info):
        # Extract undefined variable
        match = re.search(r"name '(\w+)' is not defined", error_msg)
        if match:
            undefined_name = match.group(1)
            return {
                "fix_scope": "single_line",
                "suggested_fix": f"Import or create: {undefined_name}"
            }
        return {"fix_scope": "single_line"}
What it means
Error type dispatch: Different error types get different analyzers. This is the Strategy pattern — each error has specialized handling logic.
Regex parsing: Extract structured information from Python's error messages. Find the line number, variable name, or function name.
Scope determination: The analyzer returns fix_scope which tells the fixer how much code to regenerate. NameError is usually single-line, TypeError might be function-level.
Suggested fix: Not just "there's an error" — the analyzer suggests what might be wrong ("Import or create: VGroup"). This suggestion goes into the fix prompt.

Common Error Patterns

ScopeRefineFixer recognizes these Manim-specific error patterns:

📛
NameError
Undefined variables or typos. Example: VGropu instead of VGroup. Fix: Single-line correction.
⚙️
AttributeError
Calling methods that don't exist. Example: circle.set_colour() (should be set_color). Fix: Single-line or function-level.
🔢
TypeError
Wrong number or type of arguments. Example: Text("hello", color=RED, font_size=48, unknown_param=True). Fix: Function-level regeneration.

Putting It All Together

The complete Code2Video architecture and practical usage

The Full System Architecture

Let's review the complete flow from start to finish:

1
User provides a knowledge point

Example: "Explain how transformers work in machine learning"

2
TeachingVideoAgent generates outline

Calls LLM API (Claude/GPT-4) to break topic into 3-5 teachable sections. Tracks tokens used.

3
Agent generates storyboard

For each section, asks LLM to describe animations in detail. Optionally downloads external assets (icons, diagrams).

4
Agent generates Manim code

Translates animation descriptions into executable Python. Uses parallel ThreadPoolExecutor for speed (6 sections at once).

5
ScopeRefineFixer debugs code

Runs manim command to render. If errors occur, analyzes them and applies targeted fixes (single-line, function, or section regeneration).

6
Critic provides feedback (optional)

If use_feedback=True, Gemini watches each video and suggests layout improvements. Agent regenerates code with feedback integrated.

7
Videos are merged

All section MP4 files are concatenated using FFmpeg into one final educational video.

Key Configuration Options

Code2Video is highly configurable through RunConfig:

🎛️
use_feedback
Enable/disable multimodal LLM critique. Increases quality but costs more tokens. Default: False.
🖼️
use_assets
Automatically download icons and images from external APIs. Makes videos more visually rich. Default: False.
🔢
max_fix_bug_tries
How many times to attempt error fixing before giving up. Default: 10.
🔄
feedback_rounds
How many critique-regenerate cycles to run per section. Default: 2.

Practical Tips for Using Code2Video

💡
Best Practices

1. Start with simple topics: Test with "Explain binary search" before trying "The full history of quantum mechanics."

2. Monitor token usage: Each video prints total tokens consumed. Use this to estimate costs before running batches.

3. Use parallel processing: Set parallel=True and batch_size=3 to process multiple knowledge points concurrently.

4. Enable feedback selectively: For draft videos, skip use_feedback. For final polished versions, enable it.

5. Check intermediate outputs: Inspect outline.json and storyboard.json to debug issues before waiting for full renders.
